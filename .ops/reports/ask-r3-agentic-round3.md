The empty answers were produced before the writer, rather than by an empty model completion. The record renderer recognised `bilks`/`bils`, so `focussedIds()` found a complete count answer. The loop's later `factLines()` check used a different spelling/intent test and rejected every selected count. After two rejected answer attempts, `salvage()` composed those zero remaining facts as `answer_decision: answer`. With no sources, `writeRun()` skipped the writer. That empty successful payload reached the route. The saved run 7 rejections say `count does not answer what was debated; use source passages`, despite these questions asking for bill counts or names.

Record intent now uses one shared interpretation of common spelling slips, list requests and count requests. Salvage only composes surviving facts; composition itself has a non-empty fallback. The shared response boundary independently enforces the invariant before language cleanup and after grounding, for JSON, SSE and cache replay. It can rebuild an empty answer from checked, on-topic, in-period tool evidence. Otherwise it returns non-empty decline text, `answered: false`, no invented citations and no assertion of absence. Blank, whitespace, missing and null text are covered. Empty responses cannot enter the answer cache. `ANSWER_WRITING_VERSION` is now `written-answer-19-complete-records` so the old broken answers are not reused.

The focused money tests supply a model and assert that complete typed selections need no writing call. They exercise the saved pre-writer evidence through writing, grounding and the shared response boundary, so a later writing turn cannot silently lose the second party or ranking lead.

The loop's low latency was not itself a budget failure in these cases. Useful evidence was already present; inconsistent intent checks, an incomplete count/list terminal condition, or writing losses prevented it reaching the answer. A correct exact count or list can still finish in two turns. Increasing budgets further would not have fixed these failures.

Recovery is enforced for absence and decline paths: `no_record` still requires a distinct lookup after an observed miss, and the whole-year/chamber/party count verification remains. Verified zero counts now also create a recovery obligation. They remain count evidence, rather than being mislabeled as a coverage-only result, and become answerable after recovery. While recovery is owed, the scheduler does not force an early terminal call. Both `answer` and `finish` reject an all-empty/all-zero selection before it can stop the loop; empty terminal attempts cannot consume the two-answer repair allowance. Tests cover an empty discovery result followed by an attempted decline and a successful count recovery, plus a zero count followed by each terminal tool and a distinct recovery call. Existing false-premise, future, named-scope, off-scope and causal tests remain unchanged.

The budget constants are unchanged: 16 lookup calls, eight model rounds, 30-second answer target, 60-second hard request wall, 256,000 default cumulative tokens (320,000 maximum), US$0.25 per-question admission ceiling, 1,800 selection output tokens and 16,384 bytes per model-visible result. Per-IP, model and daily limits are unchanged. Complete typed findings save a writing turn. Absence checks can require an additional lookup and model observation turn. No new live latency or cost measurement was run; the lead's next gate should measure the effect against run 7's supplied p50 2.0 s, p90 5.8 s and earlier mean US$0.002.

The MN-STAT-006 duplicate failure is a grading limitation: four different published categories legitimately have equal zero values. The grouped answer is clearer and preserves those distinctions. No grader or question was changed. The other listed failures were treated as implementation issues, not grader errors.
