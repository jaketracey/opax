## Cost and publication hold

**The metadata-only publication needs no model enrichment: US$0 in model charges.** It PATCHes only `usermetadata` and `extra` on existing resources, retaining summaries and topics. It creates no resources, submits no text and queues no enrichment. Publication and enabling remain **OFF**.

A metadata PATCH **does cause re-indexing**. At pinned NucliaDB commit `d2ea91b51a456e5a181238c0f35a57d9a940511e`, `needs_resource_reindex()` explicitly includes `usermetadata`; `extra` alone is absent from that trigger. A payload with no content fields skips extraction processing through `needs_reprocess()`. Our combined PATCH therefore refreshes the index without sending content for processing. [Writer implementation](https://github.com/nuclia/nucliadb/blob/d2ea91b51a456e5a181238c0f35a57d9a940511e/nucliadb/src/nucliadb/writer/api/v1/resource.py#L712-L774).

The writer index builder replaces the existing text/filter entries for the same resource and field IDs. It updates resource metadata relations, while unchanged paragraphs and vectors are excluded. Its regression test checks matching text replacements/deletions and zero paragraph or vector deletions. The added `extra` provenance is not passed into the resource index builder. [Index builder](https://github.com/nuclia/nucliadb/blob/d2ea91b51a456e5a181238c0f35a57d9a940511e/nucliadb/src/nucliadb/ingest/orm/index_message.py#L210-L260), [regression test](https://github.com/nuclia/nucliadb/blob/d2ea91b51a456e5a181238c0f35a57d9a940511e/nucliadb/tests/ingest/integration/orm/test_index_message.py#L54-L85), [resource metadata inputs](https://github.com/nuclia/nucliadb/blob/d2ea91b51a456e5a181238c0f35a57d9a940511e/nucliadb/src/nucliadb/ingest/orm/index_message.py#L49-L67).
