# Indexable OPAX

The portal is one static page. It used to sit behind a hash router
(`#/subject/person/Anthony Albanese`), so a crawler saw one URL with one title
and a shared link previewed as the home page whatever it pointed at. It now
answers on real paths, `/subject/person/Anthony Albanese`, without becoming a
server-rendered site.

Three moving parts:

1. The Worker answers **real paths** with `index.html`, its `<head>` rewritten
   per route by `HTMLRewriter` (`portal/src/index.ts`, the section headed
   "SEO: real paths for the hash-routed app").
2. `app.js` **routes on the path**, and a delegated click listener keeps
   in-app navigation from reloading the page. The old `#/...` form is still
   understood wherever it survives and is folded to the path form on arrival.
3. `/sitemap.xml` and `/robots.txt` are generated by the Worker from the same
   data files the app reads.

## Why the Worker and not a prerender service

Everything the head needs is already a static asset next to `index.html`:
`parliamentarians.json` (1,427 people), `graph/money*.json` (donors and
parties), `reports/index.json`. The Worker reads them through its own `ASSETS`
binding, memoised per isolate, so a page costs one subrequest to the asset
layer and no network hop. Only `/doc/<slug>` needs the knowledge box, and that
call is capped (below).

`/` is never rewritten. With `run_worker_first: ["/api/*"]` the asset layer
answers the root before the Worker runs, so `portal/public/index.html` carries
the home page's own tags statically, and those are also the defaults the
rewriter overwrites on every other route.

## The route table

Every row serves `index.html` with the head rewritten. "Source" is where the
title and description come from.

| Path | Title | Description | Source | JSON-LD |
| --- | --- | --- | --- | --- |
| `/ask`, `/ask?q=` | site title, or the question | the question, framed | the `q` param | none |
| `/search`, `/search?q=` | `Search the record`, or `Search: <q>` | static, or the query | `STATIC_PAGES`, `q` param | `WebPage` |
| `/money` | `Money map` | static | `STATIC_PAGES` | `WebPage` |
| `/explore` `/chat` `/about` `/methods` `/stats` | static | static | `STATIC_PAGES` | `WebPage` |
| `/reports` | `Reports` | static | `STATIC_PAGES` | `WebPage` |
| `/reports/<slug>`, `/reports/<slug>/s/<n>` | report title | `title: blurb` | `reports/index.json` | `Article` (+ `dateModified`) |
| `/subject/person` `/subject/party` `/subject/donor` | `Parliamentarians` / `Parties` / `Donors` | static, people count live | `DIRECTORY_KINDS`, `parliamentarians.json` | `CollectionPage` |
| `/subject/person/<name>` | `<name> · OPAX` | party, chamber, speech count, years | `parliamentarians.json` | `Person` (+ `memberOf`, APH `sameAs`) |
| `/subject/party/<name>` | `<name> · OPAX` | members, speeches, disclosed receipts | `parliamentarians.json` + `graph/money*.json` | `Organization` |
| `/subject/donor/<name>` | `<name> · OPAX` | industry, total, receipts, years, source | `graph/money*.json` | `Organization`, or `Person` for an individual |
| `/subject/topic` | `Topics A-Z` | static | `TOPIC_NAMES` | `CollectionPage` |
| `/subject/topic/<slug>` | topic name | "Parliament on <topic>" | `TOPIC_NAMES` | `CollectionPage` (+ `about`) |
| `/doc/<slug>` | speaker and date, or the division's motion | summary if the record has one, else speaker, chamber, date, length | `/api/resource` | `Article` (+ `datePublished`, `author`) |

Anything else falls through to `env.ASSETS.fetch(request)` unchanged, so an
unknown path still 404s from the asset layer and every real file still serves
itself.

Rules the table obeys:

- **Descriptions are facts first.** `withTail()` appends the invitation
  ("What they said, and who funds them.") only when the whole line still fits
  158 characters; otherwise the facts stand alone, ending on a full stop rather
  than an ellipsis. Names and dollar totals vary in length, so which half gives
  way is decided per page.
- **No em dashes**, per the house style; `clip()` turns any that arrive from
  the data into commas.
- **A missing subject is not a 404.** Under the 5-speech floor of
  `parliamentarians.json`, or a donor outside the top 250, the page still
  serves 200 with a generic line, because the app queries the live index and
  usually finds something. A slug that cannot exist (an unknown report,
  an unknown topic, a document the KB does not have) serves 404 plus
  `<meta name="robots" content="noindex">` and `x-robots-tag: noindex`.
- **Names fold.** `foldName()` normalises curly apostrophes, doubled spaces and
  case, so `/subject/person/brendan o'connor` finds Brendan O'Connor and
  canonicalises to his stored spelling.
- **Jurisdictions never sum.** The money loader prefers the federal file's node
  for a label and lets a state file stand in only when the AEC has none, the
  same rule the money map follows (`docs/DATA-MONEY.md`).

### `/doc/<slug>` and the time cap

The document routes are the only ones that leave the edge. `docMeta()` races
`apiResource()` against a 2.5 s timer; if the knowledge box is slow or down the
page serves the generic "From the record" head and the app fetches the document
itself a moment later. A crawler gets a valid page either way, never a spinner
and never a 502. Both slug shapes work: `/doc/speech-100000` (speech, titled by
speaker and date) and `/doc/division-federal-senate-8368` (division, titled by
the motion, described by the vote count).

### Prerendered text

Person, party, donor, topic and report paths also get a small
`<section id="prerender">` prepended to `<main>`: the kicker, the name as an
`<h1>`, the same factual sentence as the description, and links to the four
indexes. It exists so a crawler that does not run JavaScript still reads words
and follows links into the encyclopedia. `app.js` stamps `spa-ready` on
`<html>` as it boots and `style.css` hides the block
(`.spa-ready #prerender { display: none }`), so a human never sees it and a
reader with JavaScript off keeps it.

Documents and search results have no prerender block: their content is not in a
static file, so there is nothing honest to write there.

## The three edits in app.js

Deliberately small, because four other agents edit the same file.

| Where | What |
| --- | --- |
| `siteUrl()` | Copy-link and citation URLs emit the path form: `https://opax.com.au/doc/speech-1`, not `/#/doc/speech-1`. It runs its argument through `pathFor()`, so a caller passing the older `#/...` shape still gets a clean permalink. |
| `hereRoute()`, `pathFor()`, `replaceRoute()`, `goRoute()` | The four choke points, next to `parseHash()`. `hereRoute()` is the route now showing (`location.pathname + location.search`, or a route-shaped hash while one is present); `pathFor()` turns `#/money`, `/#/money` and `/money` all into `/money`; `replaceRoute()` and `goRoute()` are the only writers. |
| `parseHash()` | Parses `hereRoute()`, so every caller (`route()`, the game dialogs' close handler) follows the path without knowing it changed. |
| Delegated `click` on `document` | An anchor whose href is a route of ours is followed in place: `preventDefault`, `pushState`, `route()`. Modified clicks, `target`, downloads, off-site links, real files (`/map`, `/reports/x.json`) and plain in-page anchors (`#main`) are left to the browser. `isRoute()` decides, from `PANELS` plus a file-extension guard. |
| `popstate` and `hashchange` | `popstate` routes (back and forward now move between real paths). `hashchange` stays for anything still assigning `location.hash`: it folds the assignment to the path form, then routes. |
| Boot block above `route()` | `BOOT_META` captures the head the Worker wrote; a route-shaped hash left over from an old link is replaced by its path form before the first `route()`. Also adds `spa-ready`. |
| `syncPathMeta()`, called at the end of `route()` | Rewrites `canonical` and `og:url` to the current route, and sets the description and the OG/Twitter title. `route()` then fires `opax:route` so `gtm.js` can count the page view a `pushState` would otherwise hide. |

`syncPathMeta()` carries one rule worth stating: while the page showing is
still the page the Worker described (its path URL equals `BOOT_META.url`), the
Worker's title and description win over the view's generic ones. Without that,
a renderer such as Googlebot would index every subject page as "OPAX
encyclopedia" and every report as "Reports · OPAX", which is exactly the
problem this whole change exists to fix. Navigate away in the app and the
view's own title takes over.

## sitemap.xml and robots.txt

`robots.txt` allows everything except `/api/` and points at the sitemap.

`sitemap.xml` is built from the data files and cached a day (`cachedJson`,
`max-age=86400`). As of 2026-09-02 it lists **2,192 URLs**:

| | count |
| --- | --- |
| home | 1 |
| static pages (`/search` `/money` `/reports` `/explore` `/about` `/methods` `/stats`) | 7 |
| reports (`lastmod` from `reports/index.json`) | 6 |
| topics index and topics | 1 + 21 |
| directory indexes | 3 |
| parties (every label either the money data or the people data knows) | 19 |
| parliamentarians | 1,427 |
| donors (federal, QLD and VIC, deduplicated by folded label) | 707 |

`/ask` and `/chat` are left out: both are states, not pages.

Escaping is belt and braces. Names go through `encodeURIComponent`, which
already turns `&` into `%26` and a space into `%20`, and the result then goes
through `escXml()`, which handles the apostrophes `encodeURIComponent` leaves
alone (`Katter's Australian Party` ships as `&apos;`). Verified: the document
parses, has no duplicate `<loc>`, and contains no bare `&`.

## Verifying a change

With `npx wrangler dev --port 8870` in `portal/`:

```
curl -s localhost:8870/subject/person/Anthony%20Albanese | head -40
curl -s localhost:8870/sitemap.xml | grep -c '<url>'
curl -s localhost:8870/robots.txt
curl -s -o /dev/null -w '%{http_code}\n' localhost:8870/reports/nope   # 404
```

The head is only half the test: the page still has to boot as an app. Load the
path URL in a real renderer (headless Chrome over CDP, not a shared browser
tab, which is backgrounded and never paints) and check four things:
`location.href` is still the path (no `#` appeared), clicking the nav gives
another clean path, `#prerender` is in the DOM but has no `offsetParent`, and
`document.title` is still the named one rather than the view's generic title.

## Internal links

Stage one of the path change is the router, not the markup: the delegated
click listener understands both forms, so every `href="#/..."` still in
`index.html` and in `app.js` navigates to a clean path. The bundled explore
modules (`money-map.js`, `statemap.js`, `quiz.js` and the rest, built from
corpuskit) write `#/...` and `/#/...` hrefs of their own and are handled the
same way, which is why the listener accepts both.

What that leaves is cosmetic and crawl-related: hovering such a link shows a
hash in the status bar, "copy link address" copies a hash, and a crawler that
does not run JavaScript follows only the prerender block's four path links.
Converting the `href` strings themselves is the second stage. Two rules make
it safe:

1. Convert through the helpers (`searchHash`, `askHash`, `subjectHash`,
   `moneyHash`, `directoryHash`) rather than by hand.
2. Fix the readers, not the helpers, where a return value is compared or
   parsed: `searchApplied` in the search form's submit handler strips
   `#/search?` off `searchHash()` to get the params key, and `openReport()`
   guards a stale fetch by testing the current route's prefix.
