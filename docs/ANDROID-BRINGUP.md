# Android bringup

Android uses the same Expo SDK 57 / React Native 0.86 application and public
catalog policy as iOS. Native application folders are generated by CNG and ignored.
The Android config plugin, local Kotlin share module and platform checks are source
controlled. Android changes do not require regenerating or signing an iOS build.

## Local builds and device runs

Use Node 24, npm 11 and Java 21. Configure `JAVA_HOME`, `ANDROID_HOME`, the shared
build gate, pasteboard lock and capacity probe in ignored `mobile/.qa.local.env`.
The build gate must allow only one native build at a time, including Gradle.
Never commit host paths, signing credentials or device evidence.

From `mobile/`, install with `npm ci`. Run these sequentially through the harness:

```sh
bash scripts/build-android.sh development
bash scripts/build-android.sh e2e
bash scripts/build-android.sh production
```

Each command prebuilds Android and runs the corresponding app Gradle task. Start
long runs detached and poll their logs; do not put builds in a shell that a tool
will time out. Output APKs and logs live under ignored `build/android/<variant>/`.
These local builds use the generated debug keystore, including `assembleRelease`.
They are arm64 only. They are not distribution-signed or uploaded anywhere.

Create owned AVD IDs `OPAX_Pixel_API36` and `OPAX_API34` with avdmanager, using the
installed API 36 Play Store and API 34 Google APIs arm64 images. Set display names
to “OPAX Pixel API36” and “OPAX API34”; avdmanager IDs cannot contain spaces.
Leave other projects' AVDs alone. Disable audio input/output in the owned AVDs.

```sh
mkdir -p private/qa
nohup bash scripts/e2e-android.sh OPAX_Pixel_API36 01 02 03 07 08 13 25 32 \
  > private/qa/android-bringup.out 2>&1 &
```

The harness waits for five-minute load below 140, then enters `qa_paste_lock_run`,
the same lock used by the iOS harness. It refuses to boot if any simulator or
emulator is already booted Mac-wide. It owns the lock throughout boot, debug
launch, journeys, clipboard verification and screenshots. No native build occurs
during that device session. It resets font scale to 1.0, calls `adb emu kill`,
stops its own processes and releases the lock. `private/qa/<run>/exit-status`
appears after cleanup. Read `restore.log` and `lock.log` as well as that status.
Never change the Mac's volume.

`OPAX_FIXTURE_PORT` must match the e2e build and run (8900–8999). Its driver port
is fixture port + 100. Android-specific flows adapt unavailable native controls
and Back navigation. Journey 03 opens the profile directly instead of rerunning 02. Shared journeys retain their original assertions. Journeys are run once;
separate captures cover all five tabs and key screens at font scales 1.0 and 2.0.
The Android clipboard check pastes through the OS into the Ask input and compares
the exact BibTeX bytes. It never submits a paid Ask request.

The preparation script creates private copies of shared flows. Android uses
Expo Router's stable tab navigator for consistent test IDs, focus-driven catalogs
and Back behavior after cold launches.
iOS keeps NativeTabs. Android exposes the shared tab test IDs, all five labels,
Material icons and at least 48 dp targets. Today uses hardware Back from pushed
bills and waits for its edition to load before scrolling. Android's smaller
viewport gives the original-source traversal a longer scroll timeout. The money
focus sheet closes with hardware Back. Capture names remain relative to
Maestro's artifact directory, then the
existing collector gathers them into the screenshot index.
The fixture enables the exact `10.0.2.2:<port>` Host alias only for Android while
still binding to loopback and rejecting other peers, hosts and paths. The harness
probes that alias before boot.

Android copies wait for the mounted root before a startup deep link: Maestro
can return from launch before React has attached its URL listener. The harness
stops on the first failed journey; completed journeys are not automatically
retried.
For a screenshot-only continuation, `OPAX_ANDROID_CAPTURES_ONLY=1` skips completed
journeys, clipboard, share and Back/location probes. Use it with preserved e2e
state and the existing debug-launch proof; the shared lock and cleanup still
cover the entire device lifetime.
The Android records flow waits for the reader container when a deep link returns
to its existing scroll position, brings its loaded title into view and lets
layout settle before scrolling. The first reader title and all content/copy
assertions remain in the flow.
Electorate captures follow the saved seat's verified record link. Chooser slugs
are not electorate IDs and must not be substituted into native detail routes.

Use `scripts/verify-android-build.py <variant> <apk> <private-output.json>` with
the configured Android SDK to inspect the packaged manifest, optimized network
resource, embedded config/bundle and local signing certificate. Run `npm run qa`
and the existing iOS production bundle/static checks for shared-code changes.

## Android voice port plan

1. Define a Kotlin Expo module against the existing typed voice bridge: states,
   captions, cancellation, connection failures and authenticated relay behavior.
   Port secure account credentials to Android Keystore and implement sign-in,
   deletion and Ask synchronization separately from audio enablement.
2. Implement AudioRecord/AudioTrack, echo cancellation and the existing PCM16
   little-endian / G.711 mu-law formats, negotiated sample rates and fractional
   25 ms chunks. Preserve bounded capture/upload/playback queues, mute semantics
   and loudness events. Handle audio focus, route changes, interruptions and
   Activity teardown; backgrounding ends the call. Keep HTTPS/WSS on the reviewed
   OPAX allow-list, refuse redirects and redact credentials from JS events.
3. Add explicit consent and request microphone permission only when starting
   Talk. Introduce Android's microphone manifest permission and Talk route/button
   together behind a reviewed Android voice flag; do not infer availability from
   a null optional module.
4. Validate bridge conformance with offline fixtures and synthetic PCM before
   audio-enabled physical-device testing on an approved host. Verify denied
   permission, interruption, cancellation, reconnect and account deletion. Audio
   testing must never change the shared Mac's volume.

## Lane 2: Android parity and polish

Cover API 34 and physical devices, minimum-SDK behavior, GPU variability,
TalkBack, font scale 2.0 layouts, long header actions, tab labels, gesture and
predictive Back, all secondary sheets, keyboard focus, orientation and OEM
system-bar contrast. Test file-sharing recipients and cache lifetime, haptic
fallbacks and offline restoration. Profile cold reader layout, long-page scrolling
and cache restoration. Review adaptive launcher assets and the
distribution ABI/size matrix. Add verified App Links only with owned-domain
`assetlinks.json` evidence. Scope Android account synchronization explicitly;
voice stays its own port lane. Play signing, store assets and publication are a
separate authorized release process.

The private run index contains measured build sizes, permissions, journey results,
screenshots and the issue table. Evidence is not committed to this public repo.
