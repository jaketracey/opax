# OPAX bills: the shared contract (phase 1, federal 2013–2026)

Four agents build this in parallel, each in its own worktree and branch. This file is the agreement between them. Read `SCOPE-BILLS.md` (in the `scope-bills` worktree, copied to `docs/SCOPE-BILLS.md` in each worktree) for the measured facts behind it. Nobody deploys; nobody touches `CACHE_EPOCH`; nobody deletes data. The database on `desktop` (`/home/jake/.cache/autoresearch/parli.db`, via `ssh desktop`) is backed up before any write (`cp parli.db parli.db.bak-bills-<date>` once, by the registry agent; others open it read-only or write only to their own tables).

## Keys and identity

- `bill_key`: `au-federal-r<billhome id>` for ParlInfo bills (e.g. `au-federal-r7531`); `au-federal-alrc-<bill_id>` only for ALRC-only rows with no billhome match. States later: `au-nsw-<id>` etc.
- Exposure drafts (a bill released by a department for consultation before ParlInfo numbers it): `au-federal-ed-<slug>-<year>`, status `exposure_draft`, kept in `scripts/bills_registry/exposure_drafts.json` and merged by the exporter; source kinds `exposure_draft` and `consultation`; summary basis `text`. The doc carries `consultation`, `related` and `became` (the ParlInfo key once introduced). See `BILLS-EXPOSURE.md` "Exposure drafts".
- KB resource slug for a bill: `bill-<bill_key>`. Labels: `kind/bill`, `state/federal`, `decade/<2010s|2020s>`, `parliament/<47>`, `status/<status>`, `sponsor_party/<party>` when known.

## Tables (SQLite on desktop; the registry agent owns creation; the others only read them or write to the table named as theirs)

- `bills_v2(bill_key PK, jurisdiction, source_system, source_id, parliament, session, title, short_title, aliases_json, introduced_date, originating_house, sponsor_name, sponsor_person_id, portfolio, status, status_raw, status_as_of, legacy_bill_id, updated_at)`
- `bill_events(bill_key, stage, date, house, event_raw, source_url)`
- `bill_sources(bill_key, kind ['billhome','text','em','em_revised','em_supp','digest','frl_act'], source_id, url, document_date, fetched_at, licence, content_hash, cache_path, outline_text NULL)` — the registry agent fetches and stores the selected EM outline (or digest purpose section) text in `outline_text`, so the summaries agent never fetches.
- `bill_summaries(bill_key, version, basis ['em','digest'], describes_version, as_of, summary_json, model, provider, prompt_version, input_tokens, output_tokens, generated_at, review_state ['draft','ok','flagged'], superseded_by)` — **owned by the summaries agent**.
- `bill_links(bill_key, kind ['division','speech','act'], target_key, rule, confidence, evidence_json, audited ['','ok','wrong'])` — owned by the registry agent (joins).

## Static projection (`portal/public/bills/`)

- `index.json`: `{ "generated_at", "count", "bills": [ { key, title, short_title, jurisdiction, parliament, introduced, originating_house, status, status_as_of, sponsor, sponsor_party, sponsor_person_id, portfolio, has_summary, summary_version, divisions, speeches, acts } ] }` (arrays sorted by introduced desc).
- `sponsor_person_id` is a string or null in both the index and detail record, and must agree between them. Sponsor summaries use the detail record's pid and printed name so a missing field in an older index cannot discard identity evidence or change the summary URL.
- `<key>.json`: `{ key, title, short_title, aliases, jurisdiction, parliament, introduced, originating_house, sponsor, sponsor_party, sponsor_person_id, portfolio, status, status_as_of, key_dates: [{stage, date, house, url}], sources: [{kind, url, document_date, licence}], summary: null | { version, basis, attribution, describes_version, as_of, sentences: [s1,s2,s3], changes: [..3-6], affected: "…", model, generated_at }, divisions: [{ key, date, house, question, stage, ayes, noes, outcome, party_splits: {party: {ayes, noes}} , url}], speeches: [{ slug, speaker, party, state, date, stage_hint, brief }], acts: [{ title, frl_uri, assent_date }] }`
- A division may also carry `title` (nonempty text), derived only from its recorded `stage`; an unnamed stage omits it. `question` retains its words and markdown after removing a leading presiding-officer or recorded speaker-name label. Existing fields and types are unchanged. The iOS bill decoder ignores unknown fields, including `title`; `votes.json` is unchanged and its `_meta.schema` remains 1.
- Added in the November 2026 data cleanup (wave 1, bills). Each is written by every export from then on; files exported earlier lack the new keys, so readers treat them as optional:
  - `sponsors: [{name, person_id, party}]` on every bill: every sponsor in the register's order, the first being `sponsor`. A private member's bill's co-sponsors come from the register's sponsor list, or from the legacy "(s) SURNAME, Given, MP..." portfolio print, which then leaves `portfolio` null. The index row carries `sponsor_count`.
  - `sponsor_party` and each `sponsors[].party` are a party name, never the source's free text. A recognised source label (`SPONSOR_PARTY_TOKENS` in `scripts/export_bills.py`) is checked against the division resolver's bounded roster periods on the introduction date. A substantive disagreement takes the dated party. A source Rex Patrick Team label versus a dated Independent label is kept and returned as a hold, regardless of person id. A person's own registered party beats Independent on either side; the accepted regional registered party bridges its party-room variants. Ordinary aliases retain the source label, then reviewed dated renames apply. A pid may correct an existing label only when the printed surname agrees. An existing source label can also be checked between agreeing observations within the same parliament; these brackets never fill a blank label or cross a general election. Missing, conflicting or held evidence retains the source label; a fresh build or explicit Records projection aborts before publication if the electorate release or Senate Handbook is unreadable. A manual retained refresh loads Evidence explicitly, keeps previously published labels and the snapshot date on an evidence outage, and exits zero. An empty label takes the bounded dated party first, then the existing `speeches.party_canonical`/member timeline fallback, else null. Labels that name no party are logged by the exporter and not published. `fill_sponsor_parties(bills, timeline=None, evidence=None, *, records=None)` mutates these fields and always returns the held naming disagreements; positional Evidence, `evidence=` and explicit `records=` use the same mutation path. Kept personal-party/Independent disagreements remain in that return value for review.
  - `status` adds `negatived`: the bill's final recorded event is a question negatived (a defeated second or third reading). `lapsed` no longer includes those. A bill negatived and later restored keeps the status of its final event.
  - `key_dates[]` rows carry `event_raw` (the register's wording for the event) and `negatived: true` on a defeated question. Exact repeats of one event are written once. `house` is `representatives`, `senate` or null, never a source column heading such as "Assent".
  - `index.json` may carry `redirects: {suppressed key: kept key}` for a reviewed duplicate record (`scripts/bills_registry/suppressed.json`, each with its source URL). The suppressed key has no file and no index row; the Worker redirects `/bill/<suppressed key>` to the kept bill. `meta.suppressed` counts them.
  - `meta.review_links_after_last_event`: division links dated after a finished bill's last recorded event, listed for review and not removed.
  - Reviewed corrections in `scripts/corrections/bill_links.json` (a division linked to the wrong bill) and `scripts/corrections/bill_acts.json` (an Act's assent date) are applied at export, each with its source URL. A correction that no longer matches its record stops the export for review.
- Added 14 November 2026 (bill endings). Readers treat both as optional; a file without them keeps its status wording:
  - `ended` and `ended_label`, on a dead bill's file and index row, straight after `status_as_of`: how the bill ended, in the register's words. The final recorded day's event names it ("Removed from the Notice Paper in accordance with (SO 42)", "Discharged from Notice Paper", "Lapsed at dissolution", "Laid aside", a negatived question) when it names exactly one ending; otherwise ParlInfo's status text does ("Not Proceeding"). Values and labels: `negatived` Voted down, `discharged` Discharged from the Notice Paper, `removed` Removed from the Notice Paper, `withdrawn` Withdrawn, `laid_aside` Laid aside, `not_proceeding` Not proceeding, `lapsed` Lapsed. A bill still alive or passed, or one whose record names no ending, has neither field. `status` (with `negatived`) is unchanged, so a reader that ignores the pair sees what it saw before.
- The exposure agent writes the generator (`scripts/export_bills.py`) that produces both from the tables; the UI agent builds against a fixture produced by running that generator on the existing ALRC rows (no summaries) until real data lands.

## Summary contract (the summaries agent's generator)

Input: `outline_text` (EM outline or digest purpose section) plus registry metadata. Output JSON: `{ "sentences": [3 plain-English sentences], "changes": [3–6 factual bullets], "affected": "one sentence", "confidence": "high|medium|low", "flags": [] }`. Attribution line stored with the summary: `Written by a model from the explanatory memorandum; not the record` (or `…from the Bills Digest…`). Never republish EM or digest text verbatim beyond short quoted phrases; the summary is the model's own words about the facts. Model: `deepseek/deepseek-v4-flash` through OpenRouter (`OPENROUTER_API_KEY` in `.env`), `reasoning: {enabled:false}`, JSON output; budget cap $10 for the whole phase, tracked from response usage and printed at the end.

## Portal (the exposure and UI agents)

- Worker: add `bill` to the `KINDS` allowlist for search and ask filters; a `/bill/<key>` SEO route serving the app shell with title and description from `index.json`; no new generation.
- KB: `scripts/publish_bills.py` (exposure agent) upserts `bill-<key>` resources with the summary text as the body, structured data in `extra.metadata`, and the labels above; idempotent by content hash; capped at 3,500 resources; never deletes.
- UI: route `/bill/<key>` in app.js; person vote lists open a summary disclosure on tap; party pages list bill divisions with party splits; document pages attach a bill panel when the speech's title matches a bill; the Time Machine lists a year's bills. Bill lookup failure never hides a vote.
