Use OPAX in your AI tool

OPAX has a connector for AI assistants. Add it once, and your assistant can search Australian speeches, votes, bills, donations, grants and contracts on OPAX and link every answer to the official record. It is free and read-only, and it works without an account.

What it is

The connector uses the Model Context Protocol (MCP), an open standard most AI assistants support. Your assistant sends a search or a record request to OPAX, and OPAX returns the records with their source links. OPAX does not write the answer and does not see your conversation, only the requests your assistant sends.

The tools only read the public record. They cannot post, change anything or see anyone's account.

The address

There are two addresses for the same tools. Pick one.

  • No account: https://opax.com.au/mcp. Nothing to sign in to.
  • With your OPAX account: https://opax.com.au/mcp/member. Your assistant opens an OPAX sign-in page and asks you to allow it. You get your own limit of 60 requests a minute. An OPAX account is free and needs only an email address.

What the tools do

  • search_records: search speeches, bills, votes, press releases, grants and other records by words, person, party, chamber and date.
  • read_record: open one record in full, with its official source link.
  • find_connections: find recorded links between people, parties and organisations, such as donations, meetings and declared interests. A recorded link is not evidence of influence.
  • corpus_coverage: see what OPAX holds, collection by collection, and how current each one is.
  • read_grant_recipient and read_grant_program: open a grant recipient or a grant program, with totals and individual grants.

More tools cover registers and published reports. Your assistant reads the current list and how to use each tool when it connects. The Methods page has the reference.

Claude

  1. Open Customize, then Connectors.
  2. Choose Add, then Add custom connector.
  3. Name it OPAX and paste https://opax.com.au/mcp. To use your OPAX account, paste https://opax.com.au/mcp/member instead.
  4. Choose Add. With the account address, choose Connect, sign in to OPAX and choose Allow.

On a Team or Enterprise plan, an owner adds the connector in the organisation's settings first.

ChatGPT

  1. Custom connectors need developer mode, which is available on some ChatGPT plans. Turn it on in Settings under Apps and connectors.
  2. Choose to add a custom MCP server.
  3. Name it OPAX and paste https://opax.com.au/mcp, with no authentication. To use your OPAX account, paste https://opax.com.au/mcp/member and choose OAuth.
  4. Create it. With the account address, sign in to OPAX and choose Allow when ChatGPT opens the page.

Claude Code

Run this in your terminal:

claude mcp add --transport http opax https://opax.com.au/mcp

To use your OPAX account, add the account address, then type /mcp inside Claude Code, pick OPAX and sign in:

claude mcp add --transport http opax https://opax.com.au/mcp/member

Cursor

Open ~/.cursor/mcp.json and add OPAX inside mcpServers:

{
  "mcpServers": {
    "opax": { "url": "https://opax.com.au/mcp" }
  }
}

To use your OPAX account, use https://opax.com.au/mcp/member. Cursor shows a sign-in button beside OPAX in its MCP settings.

VS Code

Run this in your terminal:

code --add-mcp '{"name":"opax","type":"http","url":"https://opax.com.au/mcp"}'

Or add it to .vscode/mcp.json in a project:

{
  "servers": {
    "opax": { "type": "http", "url": "https://opax.com.au/mcp" }
  }
}

To use your OPAX account, use https://opax.com.au/mcp/member. VS Code asks you to sign in when it starts the server.

Other tools

Add a remote MCP server that uses Streamable HTTP, with the address https://opax.com.au/mcp. No authentication is needed.

If your tool cannot sign in: use a key

Some tools only accept a fixed header. For those, create an API key in your OPAX account and send it as a header with either address:

Authorization: Bearer opax_your_key

In Claude Code, for example:

claude mcp add --transport http opax https://opax.com.au/mcp --header "Authorization: Bearer opax_your_key"

A key lasts 90 days. Keep it private, and remove it in your account if it is ever shared by mistake.

What signing in allows

When you sign in, OPAX shows the name the app gives and where it will send you back, and asks you to allow it. Allowing lets that app read public records as you, under your own limit. It cannot see your email address, reading lists, messages or anything else in your account, and it cannot post.

You can see the apps you have connected and remove any of them in your OPAX account. A removed app stops working straight away.

Limits

  • No account: 60 requests a minute for one conversation or app. There is also a ceiling for each network address and for everyone together, so at a busy time a request can be turned away.
  • With an account or a key: 60 tool requests a minute, yours alone.

If a limit is reached, the tool returns a message saying so. Wait a minute and try again. Very large records are shortened and say so.

If something goes wrong

  • The tool says there were too many requests: wait a minute. If it keeps happening, use the account address so you have your own limit.
  • The assistant asks you to sign in again: the connection lapsed or was removed. Connect again from the assistant.
  • The sign-in page says the app is not recognised: remove OPAX from the assistant and add it again.
  • A tool returned something wrong, or a record is missing: email support@opax.com.au with what you asked and what came back. What OPAX receives when a tool is used is on the Privacy page.

Check and cite

Every result carries a link to the OPAX page and to the official source. Ask your assistant to show them, and check the record before you quote it. Summaries marked as machine-written are OPAX text, not the official record. How to cite is on the Methods page.
